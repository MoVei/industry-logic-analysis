# Case 02：消费品链条分析（未指定现象，须自主挖掘矛盾）

## 输入

```
看看现制茶饮 15 元以下价格带。听说门店数在涨，但好像闭店也很多。
```

## 前置条件

- 台账已有若干条记录，但无「现制茶饮」
- 无该行业 SOP
- 用户给了一个**待验证的说法**而非明确现象

## 执行步骤（期望轨迹）

1. Phase 0：归类 C 类；边界锁定为某价格带的连锁茶饮；**Phase 1 须主动挖出自洽的矛盾**（如新增门店与净增门店的剪刀差）
2. Phase 1：需求分层分析；单 UE 是否成立；替代效应（瓶装饮料、咖啡、其他价格带）
3. Phase 2：链条为「原料 → 品牌方 → 加盟商 → 外卖平台 → 消费者」；**利润池判定须区分品牌方与加盟商**
4. Phase 3：杠杆应为加盟商单店模型相关的机制（如「闭店率滞后于单店营收下滑 N 个月」这类可量化传导）
5. Phase 4：三重验证，特别注意「门店数」类数据的口径（累计 vs 净增 vs 在营）
6. Phase 5：长文产出
7. Phase 6：沉淀 `consumer-tea-chain.md`，Draft

## 关键区分点

这个用例考察三件事：

1. **能否在用户没给现象时自己挖出矛盾**（Phase 0.4 的纪律）
2. **能否识别口径陷阱**（门店数是最容易混淆的量）
3. **利润池是否真的被算出来**，而不是停留在「品牌方赚加盟费」这种表层描述
