# Case 08：集索引收口检查（v1.7.0）

> 守护一件事：**索引自己也得过关，不能只把篇目登记上去就算完**。
> README 侧有 C1—C4，本用例覆盖索引侧的 S1—S5 五种收口缺陷。
> 五条判定都在 `check-ledger.py --series` 里，失败退出码 2。

---

## 8A：三节被填成同一串

### 输入

```
给光伏硅料收口第 01 篇，把已覆盖清单补一下。
```

### 前置条件

- 篇目表已登记第 01 篇
- 该篇是冷启动开篇，同时涉及子方向、视角、生活入口三项

### 病态输出

「已覆盖子方向」「已用切入视角」「已用生活入口」三节被写成同一串子方向列表：

```
### 已覆盖子方向
- 硅料的产能—开工率—库存三层结构
- 装机政策时钟仅引入未拆解

### 已用切入视角
- 硅料的产能—开工率—库存三层结构
- 装机政策时钟仅引入未拆解

### 已用生活入口
- 硅料的产能—开工率—库存三层结构
- 装机政策时钟仅引入未拆解
```

### 期望轨迹

1. `--series` 报 **S1 失败**：`子方向＝视角；子方向＝生活入口；视角＝生活入口`
2. 按三节职责重写：子方向写「拆过哪块地」，视角写「用什么角度拆的」，生活入口写「从哪个场景入场」
3. 生活入口补回真实场景（本例为一吨硅料的价格对照：顶部买宝马、现在买五菱）
4. 复跑退出码 0

### 验证项

| # | 断言 | 检查方式 |
|---|---|---|
| E1 | S1 能报出三对相同的组合，而不是只报「有一处重复」 | 脚本输出 |
| E2 | 三节重写后内容两两不同 | 脚本 S1 通过 |
| E3 | 生活入口一行是场景，不是观点或子方向 | 人工读索引 |

**一票否决**：把三节改成「文字略有差异但仍是同一件事」来骗过 S1。

## 8B：同一节内出现重复条目

### 输入

```
碳酸锂第 02 篇收口，更新已覆盖清单。
```

### 前置条件

- 第 01、02 篇都已登记
- 「已用生活入口」应有 2 条：01 的统计局价格表缺席、02 的 IGO 两份文件

### 病态输出

该节写了 3 条，第 1 条与第 3 条一字不差（同一篇的同一个入口被回写两次）。

### 期望轨迹

1. `--series` 报 **S2 失败**：`已用生活入口 重复 1 条：<条目缩略>`
2. 删除重复项，保留 2 条
3. 在索引「维护记录」追加一行，写明是回写时引入、不是正文错误
4. 复跑退出码 0

### 验证项

| # | 断言 | 检查方式 |
|---|---|---|
| E4 | S2 指出具体是哪一节、重复几条 | 脚本输出 |
| E5 | 去重后该节条数等于实际生活入口数 | 人工核对篇目表 |
| E6 | 维护记录有该次修正留痕 | 读索引 |

**一票否决**：删条目但不留痕，导致下次误判该篇没有生活入口。

## 8C：篇目表残留占位

### 输入

```
黄金第 01 篇先登记为在写，正文还没定稿。
```

### 前置条件

- 五件套未齐，正文未写

### 病态输出

篇目表「那根杠杆」一格写 `待成稿后回填`；或某格写 `<杠杆>` 这类模板占位。

### 期望轨迹

1. `--series` 报 **S3 失败**：`1 处：待成稿后回填`
2. 成稿后按正文与 SOP 原文回填该格；确实无来源时写「缺口：<缺什么>」，不留空壳
3. 复跑退出码 0

### 验证项

| # | 断言 | 检查方式 |
|---|---|---|
| E7 | S3 只命中篇目表与四节条目，不误伤维护记录里的修正历史 | 在含有历史记录的索引上跑，应通过 |
| E8 | 占位清除后该格是实义内容或明确的缺口说明 | 人工读索引 |

**一票否决**：把「待回填」改成「待补充」等近义词继续留着——S3 的占位词表已覆盖同类写法。

## 8D：索引缺失或篇目表为空

### 输入

```
接着写碳酸锂第三篇。
```

### 前置条件

- `产出/碳酸锂/` 下已有 `01-…/`、`02-…/`
- `_系列索引.md` 被误删，或篇目表仍是空表

### 期望轨迹

1. `--series` 报 **S4 失败**：`索引缺失，但磁盘已有 2 个篇目目录` / `篇目表 0 行，但磁盘已有 2 个篇目目录`
2. 从磁盘目录与总台账回填索引，再进入 S2
3. 复跑退出码 0

### 验证项

| # | 断言 | 检查方式 |
|---|---|---|
| E9 | 索引缺失且磁盘有篇目时判失败，不是「冷启动」 | 脚本 S4 |
| E10 | 索引缺失且磁盘为空时判通过（新集冷启动） | 空目录夹具 |

**一票否决**：索引缺失仍按「冷启动」放行，导致下一轮把已写过的子方向当空白。

## 8E：篇目表与磁盘目录不符

### 输入

```
黄金第 02 篇正文标题改了，目录跟着改。
```

### 前置条件

- 目录用 `git mv` 改为新名
- 篇目表「目录」列未同步

### 期望轨迹

1. `--series` 报 **S5 失败**：`表中有、盘上无：02-展开-旧标题；盘上有、表中无：02-展开-新标题`
2. 同步篇目表「目录」列
3. 复跑退出码 0

### 验证项

| # | 断言 | 检查方式 |
|---|---|---|
| E11 | S5 同时报出两个方向的不一致 | 脚本输出 |
| E12 | `存档-` 目录不计入 S5 的磁盘侧比对 | 宠物医疗集应通过 |

**一票否决**：只改磁盘不改表，或反过来只改表不改磁盘。

## 通用断言

| # | 断言 |
|---|---|
| G1 | S1—S5 任一失败，`--series` 退出码为 2，S6 判未完成，不得进入 P1 |
| G2 | 五条判定在输出里逐条列出（✅/❌ + 具体原因），不只给一个总数 |
| G3 | S3 的扫描范围只含篇目表单元格与四节条目；维护记录与正文叙述中的同类字符串不算残留 |
| G4 | 索引与 README 是两条并列的收口检查：`check-readme.py` 为 0 **且** `--series` 为 0，任务才算完成 |
