# Phase 4: 数据与逻辑校验

| | |
|---|---|
| **输入** | `1-demand.md`、`2-chain.md`、`3-mechanism.md` |
| **输出** | `4-verification.md`：逐条通过/不通过记录 + 退回决策 |
| **前置条件** | Phase 3 完成且多层分解已闭合 |
| **完成条件** | 全部进场内容通过三重验证；不通过项已触发回路 A 退回重做 |

> 这是最容易失效的关口，因为它要求对自己刚写的东西下狠手。

---

## 步骤 4.1：三重验证（逐条过滤）

每一条计划写进正文的内容，过三关：

### 第 1 关：事实性

- 能否追溯到 L0 / L1 数据源？（见 `references/sources/data-source-map.md`）
- 是转引吗？转引必须标明原始发布方
- 数据有样本偏差吗？偏差方向必须注明

**不通过判定**：只能用「媒体」「据悉」「市场普遍认为」支撑。

### 第 2 关：相关性

- 这条数据**真的作用于那根杠杆**吗？还是只是同时发生？
- 能否说出作用路径：A → B → C 的每一环？
- 换一个时期，这条关系还成立吗？

**不通过判定**：只有相关性，说不出传导路径。

### 第 3 关：可操作性

- 能否转化成**可观察、有发布频率、有阈值**的指标？
- 能查到该指标的回看历史吗？

**不通过判定**：读者看完无法据此建立自己的观察点 → **删除该条**。

## 步骤 4.2：形式校验清单

```
[ ] 每个数字带来源 + 期间 + 口径三件套
[ ] 无「尽量/适当/可以考虑/建议关注/大概率」等模糊词
[ ] 无自谦或粉饰式表述
[ ] 无估算值填补缺口
[ ] 口径不同的数字没有出现在同一句对比中
[ ] 未引用未标注发布方的高频数据
[ ] 第〇节约束全程未违反
```

## 步骤 4.3：回路 A 触发判定

```
IF 任一内容未通过三重验证
    THEN 退回 Phase 2 或 Phase 3 重做
    NOT  禁止在本阶段打补丁（补一个数据把它救回来）
```

打补丁的典型表现：补一条相关性更弱的数据来「证明」同一个结论。**宁可删掉这个论点。**

## 步骤 4.4：数据缺口登记

把找不到的、口径不明的、历史序列断裂的数据项，全部登记进数据缺口表：

| 缺口项 | 缺失原因 | 尝试过的来源 | 对结论的影响 |
|---|---|---|---|

缺口必须在最终正文里原样出现，**不估算填空**。
