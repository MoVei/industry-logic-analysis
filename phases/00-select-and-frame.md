# Phase 0: 文章集组织与选题

| | |
|---|---|
| **输入** | 用户指定的 target（可无）+ phenomenon（可无）+ subdirection / perspective（可无） |
| **输出** | `0-frame.md` + 本行业 `产出/<行业>/_系列索引.md`（新建或更新） |
| **前置条件** | 无 |
| **完成条件** | 文章集已定位或建立；已覆盖清单已生成；S1—S6 全部按序执行且留痕；钩子命中 A/B/C 之一并通过答得圆满预检；归类已定；索引已回写 |

---

## 执行顺序（强制，不允许跳步或倒序）

> 一次任务围绕**单个行业**建立一个系列。系列由多篇相互关联的长文构成。
> 组织单位从「每期产出一篇独立文章」改为「行业文章集 + 集内篇目」。

| 顺序 | 步骤 | 判定什么 | 输出 |
|---|---|---|---|
| **S1** | 锁定行业文章集 | 本次任务属于哪个行业，系列是否存在 | 文章集路径 |
| **S2** | 三源检索，建立已覆盖清单 | 该行业已经写过什么 | 已覆盖清单 |
| **S3** | 判定目标具体度 | 用户给的是行业名还是明确子方向 | 具体 / 不具体 |
| **S4** | 分支裁决 | 具体→独立性；不具体→去重换视角或冷启动 | 本篇子方向与视角 |
| **S5** | 排序归位 | 本篇放在系列第几位 | 排序位次（软约束） |
| **S6** | 登记索引写回 | 把本篇写进索引与总台账 | 更新后的索引 |
| → | **Part II** | 单篇质量门禁（原有规则） | 合格的钩子与边界 |

**顺序不可逆的理由**：S2 的已覆盖清单是 S3 之外所有分支判断的唯一数据基础；S4 的裁决依赖 S2 与 S3 的结果；S6 的写回内容来自 S4 与 S5 的产出。先定题再检索会直接造成重复选题。

> Part II 在 S6 之后执行。S1—S6 决定「写这个行业里的哪一篇」，Part II 决定「这一篇够不够格写」。两者不可合并。

## S1 锁定行业文章集（任何输入都先执行）

**组织单位定义**

| 对象 | 路径 | 说明 |
|---|---|---|
| 文章集（Series） | `产出/<行业>/` | 该行业全部长文的集合，一次任务只围绕一个行业 |
| 系列索引 | `产出/<行业>/_系列索引.md` | 文章集目录，模板 `assets/templates/series-index-template.md` |
| 集内篇目 | `产出/<行业>/NN-<阶段>-<标题>/` | 第 NN 篇。**NN 为集内顺序号（01、02…），非全局流水号；`<阶段>` 取开篇／展开／深挖／反例／边界之一，`<标题>` 取自该篇正文首行标题的缩略** |

**执行**

```
IF 用户给了行业，或可从 target 消歧出行业
    THEN 定位 `产出/<行业>/`
IF 该目录不存在
    THEN 新建文章集，从模板生成 `_系列索引.md` 骨架
IF 该目录已存在但无 `_系列索引.md`
    THEN 补建索引，并从已有 `NN-*-<标题>/` 产出回填篇目表
    AND  回填只登记已写明的子方向与视角，不推测未记录的字段
IF 已有索引
    THEN 直接读取，进入 S2
IF 用户给了多个行业
    THEN 拆成多次任务，各自建集，不在一次任务里混写两个行业
```

> 已有的 `产出/宠物医疗/`、`产出/生猪养殖/`、`产出/碳酸锂/` 等行业目录直接成为文章集；集内篇目目录自 v1.4.0 起统一改名为 `NN-<阶段>-<标题>`（2026-11-03 已完成存量迁移）。

## S2 三源检索，建立已覆盖清单（组织判断的数据基础，不可跳过）

按固定顺序检索三处，任一处命中都计入：

| 源 | 路径 | 取什么 |
|---|---|---|
| ① 文章集总台账 | `references/ledger-analysis-topics.md` §文章集注册表 | 该行业是否已建集、已收录篇数 |
| ② 本集索引 | `产出/<行业>/_系列索引.md` §篇目表 / §已覆盖清单 | 已覆盖子方向、视角、生活入口、钩子类型 |
| ③ 实际产出目录 | `产出/<行业>/NN-*-<标题>/` 的 `0-frame.md` / `正文.md` | 索引缺记时补齐，交叉核对 |

执行：`python scripts/helpers/check-ledger.py --series "<行业>"`

合并去重后写出**已覆盖清单**，四项必列：

1. 已覆盖子方向
2. 已用切入视角 / 那根杠杆
3. 已用生活入口（不得复用）
4. 已有钩子类型分布（A / B / C 各几篇）

判定：`集内已收录篇数 > 0` 或 `三源中任一篇目存在` → **已有研究**；否则 → **冷启动**。

## S3 判定目标具体度

| 判定 | 输入形态 |
|---|---|
| **具体** | 给出明确子方向 / 切入视角 / 反直觉现象 / 具体环节。例如「写二次育肥的供给开关」「为什么砍了母猪猪价还跌」「只看持证资格结构」 |
| **不具体** | 只给行业名（「分析一下宠物医疗」），或「继续写」「下一个」「随便写点」「这个行业还能写什么」 |

`phenomenon` 非空即判为具体；`subdirection` / `perspective` 非空即判为具体；`target` 只到行业层级且无任何补充 → 不具体。

## S4 分支裁决（严格按 S3 结果二选一，不混淆）

### S4-A 目标具体 → 独立性检查

```
IF 该子方向 / 视角已在 S2 已覆盖清单
    THEN 不重复原主题，换一个未覆盖的子方向或视角
IF 未覆盖
    THEN 采纳，并写出「与已有各篇的关系」
```

「关系」四选一，必须落到具体篇号：

- **承接**：第 NN 篇引出的变量，本篇展开
- **并列**：同一主线的另一环节，与第 NN 篇互不依赖
- **递进**：在第 NN 篇的机制上再进一层
- **补反例**：第 NN 篇的结论在本篇条件下不成立

### S4-B 目标不具体，且 S2 判定「已有研究」→ 去重换视角 ★

- **不重复原主题**。从已覆盖清单的空白处选一个新子方向或新视角切入
- 必须简要说明它与已有内容的关系（承接 / 并列 / 递进 / 补反例，落到具体篇号）
- 换角度的优先级：未覆盖的子方向 > 未用过的视角 > 未用过的钩子类型
- 三级角度优先于二级：同一行业继续写，靠换子方向与视角，不靠换行业名

### S4-C 目标不具体，且 S2 判定「冷启动」→ 基础逻辑开篇 ★

- 选定该行业**最容易理解、同时最为关键**的基础逻辑，作为文章集第 01 篇
- **最容易理解**判据：读者日常能碰到，一段生活场景就能入场，不需要先懂行业术语
- **最为关键**判据：它是后续所有子方向的共同前置——不先讲清它，后面每一篇都要回头补
- 两类判据同时满足才选；只满足其一 → 继续找，不将就
- 冷启动篇不追求冷门视角，它的任务是把**系列主线**立起来，供后续篇目承接

> S4-B 与 S4-C 的先后：**先判「是否已有研究」，再决定切换还是开篇**。
> 已有研究一律走 S4-B，不得因为「想写个基础入门」而重复开篇。

## S5 排序归位（软约束，内容价值优先）★

默认：文章集按**由浅入深**排列——基础逻辑 → 单一机制 → 多层叠加 → 反例与边界。

**排序是软约束，不是硬性约束。** 落位前先做一次价值校验：

```
IF 按递进顺序排，会把后续篇目带离该行业主线
    OR 为凑「更浅 / 更深」而必须选一个低价值主题
    OR 某个高价值主题只能在当前位置讲清（错过就失去当期性）
    THEN 调整顺序，或更换更合适的主题
    AND  在索引 §排序说明 写明调整理由
```

判定优先级：**内容价值 > 由浅入深的形式**。
不得为了维持递进外观，把关键主题推后或塞入凑数篇目。

> 一次任务可以规划多篇：本次至少完成 1 篇并登记索引，其余篇目列入索引 §待覆盖方向，标注「规划」，在后续任务按序列续写。

## S6 登记索引写回（闭环，供下次 S2 使用）

S5 结束后**立即**更新 `产出/<行业>/_系列索引.md`：

| 动作 | 内容 |
|---|---|
| 篇目表追加一行 | 序号 / 目录 / 子方向 / 切入视角 / 钩子类型 / 那根杠杆 / 生活入口 / 与已有篇的关系 / 状态 |
| 已覆盖清单追加 | 本篇新占用的子方向、视角、生活入口、钩子类型 |
| 待覆盖方向更新 | 移除已被本篇占用的条目；补上本篇新引出的方向 |
| 排序说明 | 记录位次理由；若调整了默认递进顺序，写明原因 |
| 文章集卡 | 更新已收录篇数、最近更新、系列主线 |

再同步 `references/ledger-analysis-topics.md` §文章集注册表的「已收录篇数 / 最近更新」。

**读在 S2、写在 S6**，构成闭环。索引未回写视为本阶段未完成。

## Part II 单篇质量门禁（原有规则，保留）

> Part I 已锁定行业、子方向与位次。本部分的 0.2 自动选题**不再另选行业**，只在 S4 给定的子方向内执行五维打分与留痕；0.4 / 0.4A / 0.4B 检验的是这一篇的钩子质量。
> 若本部分判定换题，**回 S4 重选子方向并重走 S6**，不回到全局自动选题。

### 步骤 0.2：五维打分与自动选题（三级池）

```
一级：行业大类      → references/research/01-industry-taxonomy.md 的 A—G
二级：细分行业      → 生猪养殖 / 晶圆代工 / 现制茶饮
三级：细分环节或角度 → 生猪 → 二次育肥的供给开关
```

**三级优先于二级**：同一二级行业已有分析时，优先换三级角度（二级间隔 ≥6 期，三级间隔 ≥12 期）。
在文章集内，这条等价于 S4-B 的「换子方向与视角」。

| 维度 | 权重 | 判定口径 | 否决线 |
|------|------|---------|--------|
| 数据可查性 | 一票否决 | 先做 1—2 次实际检索，确认 L0/L1/L2 各至少一类可得 | 撑不住就换，台账注明「数据不足已跳过」 |
| 生活可感性 | 1—5 | 读者日常能否碰到 | <2 淘汰 |
| 机制独特性 | 1—5 | 有没有一条别的行业没有的传导链 | **<3 淘汰**（生命线） |
| 新颖性 | 1—5 | 台账 + 本集索引查重 | 间隔不达标淘汰 |
| 当期性 | 加分 | 近期有无矛盾现象 | — |

执行：`python scripts/helpers/check-ledger.py --suggest`（返回未覆盖且间隔达标的候选）。

> 自动选题不需要用户确认。打分明细写进 `0-frame.md` 留痕即可。

### 步骤 0.3：边界确认

用户给的标的必须满足**边界可界定**。不合格形态与收窄要求见 SKILL.md 输入规范的质量线。

收窄后必须写出 `0-frame.md` 的边界声明，包含：

- **本期覆盖**：具体到哪个环节
- **本期不覆盖**：明确排除项（参考生猪那期显式排除进口猪肉与屠宰环节）
- **时间范围**：数据取到哪一期
- **地理范围**：全球 / 中国 / 某区域

### 步骤 0.4：确定钩子（本期主线）

优先顺序：

1. 用户给了 phenomenon → 直接用作钩子
2. 没有现象 → 在 Phase 1 检索时主动挖掘当期矛盾：「按常识应该 A，实际却是 B」
3. **找不到任何矛盾就换标的** —— 没有矛盾的分析必然写成百科词条

钩子判据：能用一句大白话讲清，且答案不是显而易见的。

### 步骤 0.4A：钩子类型硬筛 ★（三选一，不命中就换题）

**仅满足「有矛盾」不够。** 矛盾分两个层级：

- 低层级：**量的问题**——「A 比 B 多了多少，这个差由哪几项构成」。这类问题导向「分解」，分解完就结束，写不出机制。
- 高层级：**性质的问题**——某个方向、符号、理论预期发生了翻转。这类问题才逼得出机制。

钩子必须命中以下三类之一，否则**判定为低层级问题，回 S4 换角度或换标的**：

| 类型 | 长什么样 | 判据 | 参照系实例 |
|---|---|---|---|
| **A 方向翻转** | 某个量的符号、收付方向、上下游地位发生反转 | 能用「本来是 X 给 Y 钱，现在是 Y 给 X 钱」「本来 +，现在 −」讲清 | 铜：加工费 +88 → −241；铝：为产铜而产酸 → 为保利而产酸 |
| **B 理论反例** | 按教科书 / 行业常识不该发生，却持续发生了 | 能说出「按 XX 理论应该 A，实际却是 B，且已持续 N 个月」 | 铝：周期性行业全行业盈利且不止一年；铜：亏钱却不减产 |
| **C 被算错的流行数** | 一个广泛传播的数字，重算后差一个数量级 | 能指出流传值、重算值与倍数差 | 铝：CBAM「省 700—1,100 欧元/吨」实为约 2.98 欧元/吨，差 235—369 倍 |

> **C 类自带高价值**：纠偏本身就是内容，制造的是「你不知道你错了」的增量，比补充信息更值钱。每期至少检索一次本行业是否有此类流行误读。

### 步骤 0.4B：答得圆满预检 ★（防带着残差往下跑）

选定钩子后，先自问一句：

> **这个问题，在现有可得数据下能不能答到闭合？**

预判方法：把钩子翻译成一个算式，看每一项是否都能取到 L0/L1。
若核心项已知取不到（例如「22% 增长 − 5% 数量 = 17 个点，但这 17 个点内部怎么分，没有可闭合数据」），**现在就换角度**，不要等到 Phase 3 才发现。

**闭环判据**：钩子的答案必须由「本文自算 + 可追溯数据」构成。若答案只能表述为「第三方测算显示……」，即为不圆满。

> 参照系从不出现「题提出来了但答不圆满」的情况——因为它挑题时就筛掉了答不圆满的。**答不圆满不是取证不力，是题没选对。**

### 步骤 0.5：归类与初始化

- 判定所属大类（A—G），记录该类「主链条假设」，**必须在 Phase 2 用实证检验这条假设，照抄算缺陷**
- 执行 `python scripts/helpers/init-analysis.py --target "<行业>"` 生成本篇工作目录、集内序号与索引骨架

## 反馈规则

```
IF 未执行 S2 就定了子方向
    THEN 判定流程违规，重走 S1→S2→S3→S4
    BECAUSE 已覆盖清单是去重判断的唯一数据基础

IF 目标不具体且已有研究，却选了与已有篇相同的子方向或视角
    THEN 回 S4-B 重新换角度
    NOT  不许以「换个说法再讲一遍」放行

IF 冷启动却选了冷门 / 需先懂术语的角度开篇
    THEN 回 S4-C 重选
    BECAUSE 第 01 篇的任务是立起系列主线，不是炫技

IF 为维持「由浅入深」而把高价值主题推后，或塞入凑数篇目
    THEN 回 S5 调整顺序或换主题
    BECAUSE 内容价值优先于排序形式
```
