## 需求溯源

用户原始需求来自一个已有的《大宗商品投资常识》写作 promot，该 promot 只覆盖大宗商品。用户要求抽取其骨架，做成适用于**全部行业**的引擎，并支持细分行业 SOP 的持续沉淀。

原型 promot 的三条选品硬标准（公开资料齐全 / 生活中有接触 / 没写过）被吸收为现在的五维打分，保留了「数据可查性一票否决」这个最关键的设计。

## D1：不做单一 workflow，判定为 hybrid

- **决策**：Hybrid（流程 + 认知）
- **理由**：分析行业既有固定骨架（需求→链条→机制→校验），每个环节又必须现场判断。纯 workflow 会退化成填表，纯 cognitive 无法保证每期都跑完需求端
- **放弃**：拆成两个 Skill（一个流程一个认知）—— 增加调用负担且割裂产出

## D2：「那根杠杆」设为废稿判据，不是加分项

- **决策**：Phase 3 找不出行业独有的量化传导链 → 判定废稿，退回重做
- **理由**：这是原型 promot 产出的文章里最有价值的部分。把它降级为「建议」后，绝大多数产出会滑向百科词条
- **放弃**：把它写成 checklist 中的一项

## D3：共性骨架与特异机制明确分离

- **决策**：通用模板部分每次照做；「那根杠杆」必须现场考古，禁止套模板
- **理由**：两者混在一起是产出百科词条的最常见原因
- **配套**：`04-mechanism-pattern-library.md` 明确标注「用于识别，不用于套用」

## D4：行业分类路由表给搜索起点，不给结论

- **决策**：七类各给一条主链条假设，规定必须被当期实证修正，**照抄算缺陷**
- **理由**：给结论会让 analyst 停止思考；给起点能降低冷启动成本又不代替判断
- **放弃**：不分类（冷启动成本过高）；分到三级细分（维护成本不可控）

## D5：数据优先级分五级，L4/L5 限定三种用途

- **决策**：券商研报与媒体报道只能用于找线索、引用专家实名原话、交叉印证，**不得作为唯一来源**
- **理由**：预测值当成事实是本类分析最常见的数据污染
- **配套**：禁止估算填空；每个数字三件套（来源 + 期间 + 口径）

## D6：硬边界写入第〇节且不可覆盖

- **用户决策**：继承基本面研究硬边界
- **实施**：不预测价格 / 不给目标价 / 不择时 / 不做情绪面与技术分析 / 不做个股推荐，写为 SKILL.md 第〇节，优先级高于一切规则
- **理由**：需求端与产业链运行逻辑属基本面研究，硬边界是这类输出的安全底线
- **放弃**：做成可选开关 —— 一旦可关闭，边界等于不存在

## D7：默认输出形态为投资常识长文

- **用户决策**：默认 longform（≥3000 字），report 与 brief 保留为可切换项
- **理由**：长文的「生活入场 + 矛盾拆解」结构最能承载机制推导，且用户已有一个稳定的阅读预期

## D8：自动选题不需要用户确认

- **用户决策**：F1 规则，选出 top1 直接执行
- **理由**：用户偏好高并发、少打断的交付节奏
- **补偿**：五维打分明细必须写进 `0-frame.md` 留痕，事后可追溯为何选这个题

## D9：审校必须是独立视角且强制挑出 ≥3 个问题

- **决策**：审校换视角重跑，挑不出 3 个具体问题 = 审校没做
- **理由**：自我复读式审校通过率是 100%，没有信息量
- **配套**：回路 B，判定缺历史实证或无独家洞察则退回 Phase 3

## D10：每个 SOP 单独现场取证，不从既有产出反推

- **用户决策**：否掉了「从已有四期产出冷启动反推首批 SOP」的省事方案，改为每个 SOP 独立调查取证
- **理由**：SOP 的权威性建立在「本轮现场取证」上。转录会继承来源当时的口径与错误，且无法反向核验
- **代价**：首批 SOP 的成本显著上升，且 Skill 上线时不预置任何行业包——这是用户明确接受的取舍

## D11：与《大宗商品投资常识》定时任务并行、互不干扰

- **用户决策**：两套体系独立运行
- **实施**：本 Skill 不读写定时任务单与大宗商品常识产出目录；两套台账独立
- **边界**：选品时承认该系列已覆盖的品种，但不剥夺本 Skill 分析它们的权利——分析同一品种必须换三级角度

### D13: 按「层次」拆分内化，不整体照搬

- **决策**：跨层次通用的规则写入本 Skill 通用规则，公司层专有的沉淀为第二条轨道
- **理由**：原 Skill 在**行业层**，专家团在**公司/个股层**。强行合并会让 Skill 失焦；不合并则两套规则各自维护、同步困难
- **放弃**：只吸收四条原则敷衍了事（会丢失最有价值的执行细节）

### D14: 「四类内容必须区分」设为红线

- **决策**：披露事实 / 管理层口径 / 外部观点 / 自主推演，四类必须在文中可识别，写入 A3 红线
- **理由**：这是专家团规则里对本 Skill 增益最大的一条。分析出错多数不是数据错了，而是**把自主推演伪装成披露事实**
- **配套判据**：删去来源标注后，读者仍能否分辨某段是事实还是推演？不能 = 不合格
- **落点**：`references/research/06-team-protocol.md` 第三节；用例 E16—E20

### D15: 五角色分工映射进现有流水线，不新增并行角色树

- **决策**：把 lead / evidence / data / domain / reviewer 五个角色**映射到现有 Phase 的职责上**，不另建一套并行角色
- **理由**：现有七阶段的职责划分与专家团高度同构（P1—P2 取证取数 ≈ evidence + data；P3 ≈ domain；P4—P5 ≈ data + reviewer）。重建一套会让人不知道该听谁的
- **唯一新增的硬约束**：**同一角色不得既写又审**。这条专家团有约束，而本 Skill 原本没有写死
- **落点**：`06-team-protocol.md` 第二节的映射表

### D16: company 轨为独立轨道，Step 4 强制复用行业 SOP

- **决策**：新增 `scope=company`，走 `phases/07-company-analysis.md`；其 Step 4 必须调用对应行业的 domain playbook
- **理由**：这是两轨唯一的实质接口。没有它，公司分析会退化成「脱离行业的财报朗读」
- **反向要求**：用公司的实际数据**反向校验**行业结论，而不是照抄行业结论
- **缺失处理**：无对应行业 SOP 时，必须在报告中注明「行业结构未做完整拆解，本结论仅基于公司视角」

## D17—D19：质量校准升级（2026-11-02，对标参照系诊断）

> 触发：把本 Skill 的产出（宠物医疗第 01 期、生猪厂家结构切片）与参照系
> 《大宗商品投资常识》第 01 期·铜、第 04 期·铝做抽象层面对比，诊断出三类根本性差距。
> 完整诊断见 `C:/Users/12236/Desktop/常识/质量诊断-我的产出-vs-常识系列.md`。

### D17: 选题筛选器从「有矛盾」升级为「三选一硬筛 + 答得圆满预检」

- **决策**：P0 新增步骤 0.4A（钩子必须命中 A 方向翻转 / B 理论反例 / C 被算错的流行数）与 0.4B（答得圆满预检）
- **理由**：诊断出最根本的差距是**问题意识的层级**——我的产出问「这个差由哪几项构成」（残差归因，导向分解），参照系问「为什么会发生一件理论上不该发生的事」（性质翻转，导向机制）。**量的分解写不出机制**
- **关键判据**：宠物医疗那期自己承认「17 个百分点具体各占多少取不到可闭合数据」——**题提出来了但答不圆满**。据此定下规则：答不圆满不是取证不力，是题没选对，须在 P0 换角度而不是带着残差往下跑
- **放弃**：只在 P3 事后拦截（那时已投入大量取证成本，沉没成本会诱使执行者硬写）

### D18: 论据性质设硬律——主链自算律 + 多源闭环律

- **决策**：P4 新增步骤 4.2。核心结论必须有 ≥1 条 `L0 → 本文算术 → 结论` 的主链且列出全部输入；承载核心结论的关键量须有 ≥2 条独立来源且量级对得上
- **理由**：诊断出第二根本性差距——**参照系的结论是算出来的，我的结论是引来的**。`0.42 × 13,500 = 5,670`、`-241.17 × 3.4542 × 6.7192 = -5,597` 这类自算链不需降档；靠第三方测算支撑的结论必然降档，降档即无穿透力
- **配套**：第三方测算（沙利文、白皮书、券商、行业调研）降级为**交叉印证**，不得当主链；单一来源的量降级为**例证**，不得承载主论点
- **放弃**：把这条写成「尽量优先使用一手数据」的软建议（软建议等于没有）

### D19: 杠杆准入三问扩为四问 + 双层结构要求

- **决策**：P3 加第 4 问「必要性（反事实）」——须写出「若这根杠杆不存在，本期主现象就不会发生」；并要求杠杆必须双层：机制层（谁赚钱/份额怎么变）+ 不响应层（为什么没被竞争抹平）
- **理由**：诊断出第三类差距——我的杠杆是**单一的**，只解释「现象发生了」，解释不了「为何持续」。铝篇的杠杆是三层的且明确写「缺任何一层高利润都不成立」
- **判据**：只有机制层的判为**半根杠杆**，须回 P2 补实证，不许以「壁垒较高」这类无机制短语结案
- **放弃**：允许用「相关性强」替代反事实检验（相关性无法区分因果与共变）

### 三条改进的优先级约定

**G1 选题（D17）> G2 取证（D18）> G3 杠杆（D19）>> 表达层**。
表达层问题（开篇场景无落差、过渡注水、结尾复述、术语未贯穿）在前三项落地后重新审，届时多数会自行消失。
**不在本次改动中处理表达层**——G 层不动时改 E 层，追不上参照系。

## D20—D23：组织形态改造（2026-11-03，用户指定）

> 触发：用户要求把组织形式从「每期产出一篇独立文章」改为「以行业为单位的文章集」，
> 并调整目标不具体时的去重逻辑、冷启动优先级与排序原则。
> 约束：**保留原有写作风格与输出规范，只改造选题与组织流程**，并明确判断步骤的先后执行顺序。

### D20: 组织单位 = 行业文章集 + 集内索引

- **决策**：`产出/<行业>/` 定义为一个文章集（Series），集内多篇长文相互关联；每集维护 `_系列索引.md`（篇目表 + 已覆盖清单 + 待覆盖方向 + 排序说明）。NN 改为**集内序号**，不是全局流水号
- **理由**：原台账是全局扁平流水号，去重只能靠「隔几期」的间隔规则，管不住「同一行业换个说法再讲一遍」。按行业建集后，去重有了可枚举的清单
- **配套**：总台账升级为「文章集注册表（第一入口）+ 逐篇审计（第二层）」双层；集内去重为主，跨集间隔兜底
- **放弃**：把已有产出目录改名或移动。已有 `宠物医疗/`、`生猪养殖/`、`碳酸锂/` 直接成为文章集，零迁移成本
- **落点**：`phases/00` S1、`assets/templates/series-index-template.md`、`references/ledger-analysis-topics.md`、`init-analysis.py`

### D21: 目标不具体时，先检索既有研究，按「是否已有」分叉

- **决策**：P0 设为强制顺序链 S1→S6；其中 S2 三源检索（总台账注册表 / 本集索引 / 实际产出目录）是 S4 全部判断的唯一数据基础。目标不具体且已有研究 → **S4-B 换视角**，不重复原主题，并说明与已有篇的关系；冷启动 → **S4-C 基础逻辑开篇**
- **理由**：用户明确「目标不够具体时先检查该行业是否已存在既有研究」。把检索放在定题之前，重复选题在源头被拦下；先定题再检索等于事后补救
- **关键判据**：S4-B 与 S4-C 的先后是「先判是否已有研究，再决定切换还是开篇」。已有研究一律走 S4-B，不得因为想写基础入门而重复开篇
- **顺序不可逆**：S2 未产出已覆盖清单前不得确定子方向；S6 索引未回写前不得进入 P1
- **落点**：`phases/00` Part I、SKILL.md Part B「P0 内部执行顺序」与流程规则 F0 / F11 / F12 / F14、`check-ledger.py --series`

### D22: 冷启动选「最易理解且最关键」的基础逻辑开篇

- **决策**：该行业无任何既有研究且目标不具体时，第 01 篇选最容易理解、同时最为关键的基础逻辑；两类判据**同时满足**，只满足其一继续找
- **理由**：第 01 篇的任务是把**系列主线**立起来，供后续篇目承接。冷门视角或需先懂术语的环节，会让后面每一篇都要回头补前置
- **判据**：最易理解 = 一段生活场景即可入场、不需行业术语；最为关键 = 是后续所有子方向的共同前置
- **放弃**：冷启动也追求「新颖 / 冷门」（新颖性与开篇任务冲突）

### D23: 由浅入深是软约束，内容价值优先

- **决策**：文章集默认按由浅入深排列，但落位前先做价值校验。若递进会把后续篇目带离行业主线、为凑层次须选低价值主题、或高价值主题只在当前位置成立，**调整顺序或更换更合适的主题**，并在索引 §排序说明 写明理由
- **理由**：用户明确「不要将这一形式当作硬性约束……始终以内容价值优先」。把排序写成硬规则会诱导为形式牺牲选题质量
- **判据**：内容价值 > 排序形式。不得为维持递进外观把关键主题推后或塞入凑数篇目
- **落点**：`phases/00` S5、流程规则 F13、认知规则 C8、`topic-scoring.yaml` 的 `organization_policy.ordering.hard_constraint: false`

### 单向约束：写作风格与输出规范不变

## D26—D27：读者层与可读性门禁（2026-11-03，用户指定）

> 触发：用户对比《大宗商品投资常识》四期与 `产出/` 下的文章，判断后者「易读性不够」，先追问表层原因，
> 再要求「把易读也写进去，面向读者是外行人员」。
> 约束：只加读者层与排版门禁，**不放松任何取证纪律**。

### D26: 双轨引用——正文只写「机构 + 期间」，编号只活到底稿与附录

- **决策**：正文引用格式统一为 `（机构，期间）`，如 `（IGO 季报，2026Q3）`；底稿编号（`D501`/`C504`）与四类内容标签（`【事实】`/`【推演】`）**一律不出现在正文**，改为文末「数字与出处对照表」四列（正文位置／文中写法／编号／来源+期间+口径）。四类内容仍须区分，但用**措辞**区分（「公司在三季报里写的」「管理层在电话会上说」「有机构算过」「按上面的数自己算」）。关键换算把算式写进正文。
- **理由**：两套办法都要求数据可追溯，但常识用的是**可复算**（算式即证据，读者能跟着算），本 Skill 用的是**可回查**（编号是地址，只有检索系统能用）。实测正文引用以编号开头的比例：常识四篇 0%，产出 42% / 50% / 58%，且随门禁完善而上升——**制度在自我强化地把数据库主键印进给读者看的文章**。
- **判据**：读者读完一句，知道这话是谁说的、能不能当事实用；拿不到编号表也不损失任何信息。
- **放弃**：
  - 正文保留编号但改用上标 → 放弃。上标仍是地址，读者照样没法用。
  - 只删标签、保留编号 → 放弃。编号占 6—8 字符且每段 1.3—1.7 个，是句子被切断的主因。
  - 四类内容合并为一类 → **明确否决**。区分四类（披露事实／管理层口径／外部观点／自主推演）是 A3 红线，只换表达形式，不降要求。
- **落点**：`SKILL.md` A2/A3/输出规范、`phases/05` 5.3、`assets/templates/longform-template.md` 文末附录、`08-readability-laypeople.md` §3

### D27: 可读性进流程，读者正式定为「外行」

- **决策**：正文读者定义为「没读过该行业任何报告、但有生活常识和初中算术的成年人」。新增 `08-readability-laypeople.md` 与 `readability-check.py`，设 11 项门槛（R1—R11），其中 R6 正文编号、R7 四类标签为**一票否决**（必须为 0），其余 9 项软指标**超线 ≤3 项**为过。P5 新增「先口述、后核数」工序（5.2）与可读性门禁（5.6）。
- **理由**：用户实测反馈「产出文件夹下的文章易读性不够」。量化后确认差异不在信息量（每百字数字 4.1 vs 4.6），而在**版面颗粒度与声部**：段中位 40—69 字 vs 121—183 字、单句成段 47—63% vs 20—40%、多括注段落 8—22% vs 48—54%、旁白 0.7—1.4 处/千字 vs 0—0.16。
- **关键设计：门槛是体检项，不是写作命令**。这些数字是「段落被写成材料串」的**结果**，照着数字写会得到被砍断的句子。真正的杠杆是工序——**写正文前先合上数据表口述一遍**，因为「视线落在表格行上，一段就自然对应一组行」。
- **校准**：门槛取在两组之间且不踩边界——常识四篇 0 项超线，存量产出五篇全部一票否决失败且超线 5—9 项。脚本口径固定（正文起点＝首个二级标题；段落排除表格/标题/引用块；句子按。！？切分丢弃 ≤8 字碎片）。
- **放弃**：
  - 把 R1—R11 直接写成「写作时必须满足」→ 放弃。会把可读性变成新的八股，且实测中「照着阈值砍句」是本末倒置。
  - 用 LLM 主观打「可读性分数」→ 放弃。不可复现、不可回归。
  - 追改存量 4 篇已发布稿 → 放弃。改动面大且无读者收益；某篇被重写时按新规执行，旧稿加 `存档-` 前缀。
  - 因为「啰嗦」删掉数字或限定条件 → **明确否决**。可读性与严谨冲突时先保严谨，用「挪位置」（进附录/读法说明）解决，不删数据。
- **落点**：`SKILL.md`（frontmatter、A2、A3、校准清单、资源索引、版本历史）、`phases/05`、`assets/templates/longform-template.md`、`references/research/05-writing-dna.md` 附条 11—13、`tests/case-06`、`readability-check.py`

### 本次未改动（单向约束）

第〇节硬边界、P0 选题链（S1—S6）、五件套顺序与「正文禁未登记数字」、主链自算律与多源闭环律、

### 放弃的方案

| 方案 | 放弃原因 |
|---|---|
| 靠「记得顺手改一下」 | 已经失效一次。没有检查项的约定等于没有约定 |

| 把 README 同步放到 P6 之后统一做 | 任务可能不带 P6；且跨任务补登正是本次出问题的路径 |
| 只改篇数、不改目录树 | 目录树是读者判断集规模的第二入口，改名与 `存档-` 必须在树里体现 |

## D29：集索引的收口缺陷必须可机械判定，脚本提示须与门禁同步（2026-11-04，用户指定）

> 触发：用户在执行时发现两处缺陷——① 集索引的「三节互相复制 / 节内重复 / 占位残留」没有任何脚本能查，
> 本次靠人工读 README 才顺带撞出；② `check-ledger.py` 结尾仍提示「完成后回写本集索引与本台账注册表」，
> 与 v1.6.0 的三处回写和 F0 闸门不一致。用户确认后要求「都改掉」。

### 决策

- **`--series` 从「只读三源」升级为「读三源 + 查索引」**，新增五条判定，失败退出码 **2**（与 `--check` 的 1 区分）：

  | 码 | 判定 | 依据 |
  |---|---|---|
  | S1 | 三节（子方向／视角／生活入口）不得两两内容相同 | 光伏硅料 2026-11-04 那处三节被填成同一串 |
  | S2 | 任一节内不得出现重复条目 | 碳酸锂「已用生活入口」第 1 与第 3 条一字不差 |
  | S3 | 篇目表单元格与四节条目不得残留「待回填」等占位或 `<模板>` 占位 | 光伏篇目表「那根杠杆」曾写「待成稿后回填」 |
  | S4 | 索引须存在且篇目表非空（磁盘已有篇目目录时） | 索引是三源之一，缺失等于去重依据失效 |
  | S5 | 篇目表登记目录须在磁盘存在，磁盘篇目目录须已入表 | v1.4.0 全量改名后的高危漂移 |

- **S3 的扫描范围刻意收窄**：只扫篇目表单元格与四节条目，不扫正文叙述与维护记录。
  理由：光伏索引第 30 行与维护记录里都有「待成稿后回填」这个字符串，但那是**修正历史**，不是残留占位；全篇扫描会误伤。
- **钩子类型不参与 S1**：它是 A/B/C 计数分布，与另三节结构不同，参与比对只会制造噪音。
- **结尾提示改为三处回写**，并要求 `check-readme.py`（C1—C4）与本命令（S1—S5）同时为 0。
- **新增 `--root`** 参数指向测试夹具，使五条判定可回归。
- 新增流程规则 **F16**（内容层收口）、**F17**（结构层一致性），异常表一行、校准清单一条、case-08 用例。

### 理由

README 侧已有 C1—C4，索引侧却一条没有，而索引恰好是 S2 去重的**唯一依据**：
三节混成一串会让 S4-B 误判某角度「已被占」，或反过来漏判重复。这类错误在输出里完全静默——
`--series` 会把三节原样打印出来，看上去一切正常，函数末尾还无条件 `return 0`。

### 放弃的方案

| 方案 | 放弃原因 |
|---|---|
| 全篇正则扫「待回填」 | 会命中维护记录里的修正历史，逼人删掉真实记录 |
| 用条数判断三节是否重复 | 三节条数天然不同（子方向可 7 条、生活入口 2 条），条数相同不等于内容相同 |
| 把 S1—S5 做成与 C1—C4 同一脚本 | 两者作用对象不同：C 码查 README 与磁盘，S 码查索引内部与磁盘；塞在一起会让入口模糊 |
| 失败只打印不返回非 0 | 那就等于又一个「没有检查项的约定」，本次缺陷正是这样漏掉的 |
