# 细分行业 SOP 索引

> 每份 SOP 是**带到期日的合约**，不是写完封存的文档。
> 权威性来自可回滚、可证伪、有时间戳。

---

## 独立取证原则（最高）

```
每份 SOP 的数据与机制必须来自沉淀当期的现场检索结果
```

**禁止**：

- ❌ 从既有产出、历史文章、笔记中转录数据
- ❌ 用「之前分析过」代替本轮取证动作
- ❌ 把其他文档的结论当作本 SOP 的已验证依据

**允许**：把既有产出当作「去哪找线索」的检索起点，找到后仍须回到 L0—L2 原始发布方核对取数。

详见 `phases/06-sop-precipitation.md`。

---

## 三级定级规则

| 级别 | 门槛 | 标注要求 |
|---|---|---|
| **Draft 草案** | 完成首期分析 + ≥1 个历史实证区间 + 数据清单完整 | 使用时标注「未经滚动验证」 |
| **Verified 已验证** | 复用 ≥2 期或跨越 ≥2 个时点，且 ≥1 次机制方向判断被事后数据证实 | 标注 last_verified |
| **Authoritative 权威** | 复用 ≥3 期 + 跨越一个完整周期/阶段 + 无未决反例 | 可作为该行业基线认知 |

**初次沉淀一律 Draft。** 不允许因为「写得很完整」而跳级。

---

## 复用前的强制检查

### ① 时效检查

| 数据类型 | 重新取数阈值 |
|---|---|
| 月度数据 | >45 天 |
| 季度数据 | >105 天 |
| 年度数据 | >400 天 |

执行：`python scripts/helpers/check-sop-freshness.py --all`

### ② 反例检查

查阅该 SOP 的 `verification_log`，确认无未决反例。有未决反例 → 明示该 SOP 当前不可靠，并降为 Draft。

### ③ 每次使用后必做

在 `verification_log` 追加一行：使用日期 / 当期读数 / 机制方向是否符合预期 / 是否发现新反例 / 期号。

---

## 降级与废止

| 触发条件 | 处理 |
|---|---|
| 具体数据源停更或变更口径 | 自动降为 Draft，30 日内寻找替代源 |
| 连续 2 期机制判断被证伪 | **主链条作废**，回到 Phase 3 重新考古 |
| 行业结构发生该 SOP 定义的 X 条件 | 相关章节暂停适用 |
