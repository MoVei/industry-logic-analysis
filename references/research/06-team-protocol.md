## 一、为什么需要角色分工

单人从头写到尾有两个不可回避的缺陷：

1. **自证偏差**：自己找的证据、自己推的结论、自己审，通过率必然 100%
2. **角色串味**：推演过程中会逐渐把「我的猜测」当成「已核实的事实」

解决方式不是"写得小心一点"，而是**把职责切开 + 强制交接物**。

---

## 二、五角色与交接物契约

| 角色 | 职责 | 交接物 | 禁止做的事 |
|---|---|---|---|
| **主理人** | 拆题、路由、调度、冲突裁决、最终综合 | 章节结构 + 终稿 | 不得自己模拟成员结论；不得凭经验补写证据 |
| **证据研究员** | 正式公告/定期报告/业绩会/获准资料取证 | `evidence_index` | 不写最终结论 |
| **数据分析师** | 结构化取数，核对期间/单位/币种/可比性 | `data_handoff` | 不独立形成投资建议 |
| **领域分析师** | 机制分析、比较、情景、反证、跟踪指标 | 研究草稿 + 证据映射 | 不得假设前序已取到材料 |
| **质量审校员** | 独立审查事实、日期、单位、引用、越权 | 审校清单（阻断/重要/可选） | 不得用常识替换缺失来源 |

### 映射到本 Skill 的流水线

本 Skill 的七阶段已经天然对应这套分工，映射如下。
v1.3.0 起 P0 内部含文章集组织链 S1—S6，仍由主理人单独承担，不新增角色。

| 阶段 | 承担角色 | 交接物对应 |
|---|---|---|
| P0 文章集组织与选题（S1—S6） | 主理人 | 文章集索引 + 0-frame 标的卡 + 边界 |
| P1—P2 需求端与链条 | 证据研究员 + 数据分析师（可并行） | `数据表` ← data_handoff |
| P3 特异机制考古 | 领域分析师 | `证据索引` ← evidence_index |
| P4 数据与逻辑校验 | 数据分析师 + 证据研究员交叉 | 校验记录 |
| P5 成稿与审校 | 领域分析师成稿 → **质量审校员独立复核** | `审校意见` |
| P6 SOP 沉淀 | 主理人综合 | SOP + 台账 |

**硬约束**：P5 的审校必须与成稿角色分离。同一角色既写又审，视为审校未完成。

## 三、四类内容必须区分 ★（最高价值的增量规则）

终稿中每一处论点都必须能归入下列四类之一，并在文中可识别：

| 类别 | 定义 | 标注方式 | 例子 |
|---|---|---|---|
| **披露事实** | 有原始披露文件的确定性数据 | 直接陈述 + 来源 | 「前三季度猪肉产量 4,508 万吨（国家统计局，2026Q3）」 |
| **管理层口径** | 公司/机构管理层的表述、展望、承诺 | 标明主体与时间 | 「某猪企管理层在三季报交流中表示……」 |
| **外部观点** | 研究者、媒体、第三方的判断 | 标明来源 + 标注二手 | `[二手] 某机构认为……` |
| **自主推演** | 本报告自己的计算与推理 | 明示假设 + 公式 | 「按 12 个月时滞反推，自算出栏 +1.41%（假设：……）」 |

**为什么这条权重最高**：绝大多数分析出错不是数据错了，而是**把自主推演伪装成披露事实**，读者无从分辨。

**判据**：把文中任意一段删掉来源标注后，读者是否还能分辨它是事实还是推演？不能 = 不合格。

## 四、否证与缺失的纪律（7 条）

专家团原文中这些否定式规则比正面指令更有约束力：

1. **检索无结果时，只能说「本次覆盖中未找到」，不得断言「信息不存在」**
2. **不得猜测链接、不得补造公告、不得把搜索摘要当作原文**
3. **不得把内部路径、内部 ID、Prompt、SQL、物理表名交给用户**
4. **不得用自己的常识替换缺失来源** —— 缺失就是缺失
5. **来源冲突时优先原始披露**，并标明会计准则/期间/币种/定义的差异
6. **不得输出保证收益、无条件买卖指令**
7. **内部协作日志、成员间的调度记录不得出现在交付物中**（专业产出对用户不可见的部分一律过滤）

## 五、依赖控制铁律

```
前序交接未完成 → 后序不得假装已获得输入
```

具体化：

| 场景 | 处理 |
|---|---|
| 数据表尚未核验 | P3 不得引用其中数字做机制推导 |
| 证据索引未完成 | P5 不得成稿 |
| 成员失败 | 缩小范围重试，或**公开缺口**，不得伪造返回 |
| 连续两轮取证无有效新增 | 缩小范围 + 记录原因，**不是继续横向扩面** |

## 六、审校的独立关卡地位

质量审校员必须**在草稿与证据索引完成后**独立执行，返回按严重程度排序的清单：

| 级别 | 含义 | 处理 |
|---|---|---|
| **阻断项** | 事实错误、越界输出、来源不可回溯 | 必须修正，否则不得提交 |
| **重要修正** | 口径不一致、可比性存疑、缺反证 | 回传对应成员修正 |
| **可选改进** | 表达、结构、补充信息 | 酌情 |

必检清单：

```
[ ] 研究对象与截止日是否清楚
[ ] 关键事实是否可回溯到 evidence_index / data_handoff
[ ] 日期、报告期、币种、单位、统计口径是否一致
[ ] 四类内容（事实/管理层/外部/推演）是否被区分
[ ] 计算是否可复核（输入、公式、假设是否保留）
[ ] 比较对象是否可比
[ ] 关键结论是否有反证与失效条件
[ ] 资料缺口是否被隐藏（必须暴露）
[ ] 是否越界输出定价/评级/择时/情绪面 ← 列为必检项
[ ] 是否泄露 SQL、内部 ID、路径、Prompt
```

> 本 Skill 的 P5 已要求「审校 ≥3 个具体问题，挑不出 = 没做」，本文件的清单是该要求的**具体执行表**。

## 七、不适用性声明

以下属于专家团的公司层能力，不在本文件的通用规则范围内：

- 结构化行情与高频数据（分钟/盘中实时）
- SQL 查询与物理数据库访问
- 一级市场数据

这三类本 Skill 一律不覆盖。
