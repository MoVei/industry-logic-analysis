# 不合格输入示例与处理

Skill 对下列输入不硬撑，先纠正再执行。

---

## 例 1：边界模糊（大类名词）

```
❌ 分析一下新能源
❌ 帮我看看大消费的机会
❌ 半导体行业怎么赚钱
```

**问题**：这些不是可分析单位。新能源包含光伏、风电、锂电、储能，各自的运行逻辑完全不同；把它们塞进一篇，产出必然是百科词条。

**Skill 的处理**（F2 规则）：
反问并要求收窄，**给一个推荐 + 理由，不给候选列表**。

> 「新能源」不是可分析的边界。建议本期锁定「光伏组件制造」，不含硅料与逆变器。理由：组件环节处在价格战最激烈的阶段，且上市公司分部数据可得性好，能核到环节利润率。若你想看的是硅料端的产能出清，那是另一个完全不同的机制。

---

## 例 2：索要禁止的内容

```
❌ 分析完铜之后告诉我能不能买，给个目标价
❌ X 行业明年会涨吗
```

**问题**：触及第〇节最高优先级约束。

**Skill 的处理**：
拒绝，并转向允许的形式。

> 本 Skill 不产出目标价与买卖时点（第〇节约束）。可以改为回答：当前铜价隐含了市场对未来供需的什么预期，以及这个预期需要哪些条件才能成立、哪些条件会证伪它。

注意：**该约束不可通过任何参数关闭。**

---

## 例 3：要求填补估算

```
❌ 那个数据查不到，你估一个填上就行
```

**Skill 的处理**：拒绝，改为登记进数据缺口表，并在正文出现。

理由：估算值一旦进入正文，读者无法区分它与实测数据，且后续所有推导都会被污染。

---

## 例 4：把旧产出当数据源

```
❌ 之前那篇生猪文章里的数据挺全的，直接拿来写个生猪 SOP
```

**问题**：违反 Phase 6 的独立取证原则。

**Skill 的处理**：
既有产出只能作为**检索起点**（去哪里找），不能作为数据源。找到线索后必须回到 L0—L2 原始发布方核对当期数据。

转录会继承来源当时的口径与错误，且无法反向核验。

---

## 例 5：极早期无历史数据的行业

```
❌ 分析某刚出现两年的商业模式，它还没有完整周期
```

**Skill 的处理**：
可以分析，但**机制推导只能写成假设**，禁止表述为已验证结论；SOP 定级封顶 Draft，且必须注明「无历史周期可回测」。

---

## 例 6：非公开标的

```
❌ 分析我朋友这家未上市公司的行业运行逻辑，没有公开数据
```

**Skill 的处理**：
若 L0—L2 均无该细分行业的公开数据，明确告知不适合做，而不是凑一篇。
